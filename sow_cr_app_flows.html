App overview & data model
Core concepts, document hierarchy, and chain rules that underpin the entire application.
01
Core document types
SOW — Statement of Work

The root document. Defines the full scope of an engagement — deliverables, timeline, budget, resources, and terms. Every project starts with an SOW. Contains 6 sections: Project info, Scope, Timeline, Budget, Resources, Terms.

CR — Change Request

Extends a parent document. Captures only what is changing — scope, budget, timeline, or resources. A CR inherits all values from its parent and calculates running totals automatically. Contains fewer sections than an SOW.

Chain rules

Standard chain: SOW is root, CRs extend in sequence.

SOW as parent (default)

Every new project starts with an SOW. CRs normally link to the SOW as their parent unless explicitly set otherwise.

CR as parent (flexible)

Any CR can become the parent of a new CR. The chain can extend indefinitely. Running budget and period totals accumulate across the full chain.

Detached CR

A CR can exist without a parent if needed. All values entered manually. Useful when the original SOW is unavailable and import is not practical.

Import flow
Bringing existing SOWs or CRs into the app from old documents. Three import methods. Full review before saving.
06
Import scenarios
Scenario A

New to the app — have full history

User has the original SOW and all CRs built outside the app. Upload SOW first to establish root, then upload each CR in chain order to reconstruct the full chain.

Scenario B

New to the app — partial history

User only has the most recent CR. Upload that CR and set it as the chain root. All future CRs extend from it. The app marks it as an imported root with a note that earlier history is unavailable.

Scenario C

Ongoing user — found old SOW

User has been building CRs standalone and later finds the original SOW. Import the SOW and link existing standalone CRs to it retrospectively.

Import steps — full flow
1
Choose import method
Upload a file (Word, PDF), paste raw text, or connect a Google Doc link.
2
Extraction
App parses the document and extracts key fields. Auto-maps detected sections to the app's standard structure.
Confidence score shown per field: auto / check / not detected
3
Review extracted fields
All extracted values shown side by side with the original doc. Every field is editable regardless of confidence score.
Fields tagged: auto (detected) · check (low confidence) · not detected (manual entry needed)
4
Review section mapping
App shows how each section of the uploaded doc maps to the app's sections. User can reassign any section that was mapped incorrectly.
Unassigned sections flagged in amber — must be resolved or skipped
5
Set document type & role
Confirm: is this an SOW or a CR? If CR: set its parent (link to existing SOW or CR, or mark as chain root). If SOW: becomes root of a new or existing project.
6
Save imported document
Saved with "imported" tag. Visible in chain view. All future CRs can extend from it normally.
Imported docs are fully editable after saving

Chain interactions

Open any node

Click any SOW or CR in the sidebar to open it in the main panel. View all sections, inherited values, and running totals.

Extend any node

"Extend" button appears on every node. Creates a new CR with the clicked node as its parent. Launches the CR guided form with inherited values pre-filled.

Chain running totals

The chain header always shows the cumulative budget (sum of SOW + all CRs) and the full engagement period (earliest start to latest end date).

Origin tags

Each node shows whether it was built in the app or imported. Imported nodes show which fields were auto-extracted vs manually entered.

Reorder / relink

A CR's parent can be changed after creation (e.g. relink from CR #1 to SOW directly). The app recalculates all running totals after relinking.

Chain root options

SOW is the default root. If no SOW exists, the earliest imported CR becomes the root. Any node can be manually set as root from its settings panel.

Approval flow
Optional per document. When enabled: add approvers, they get an email link, they approve or request changes, status is tracked per person.
08
Approval flow steps
1
Enable approvals (optional toggle)
Off by default. Toggle on per document. Can be enabled or disabled while document is in Draft status.
2
Add approvers
Enter name and email for each approver. No app account required. Multiple approvers supported — all must approve before document is final.
3
Submit for approval
Each approver receives an email with a unique review link. Email contains the document summary and a direct link to the review page.
No login required for approvers
4
Approver reviews
Approver opens the link, sees a read-only view of the document, and either clicks Approve or clicks Request Changes and leaves a comment.
5
Track status
Approval panel shows each approver's status (pending / approved / changes requested), timestamp, and any comments left.
Document becomes final only when ALL approvers have approved
6
Address feedback & resubmit
If any approver requests changes: edit the document, then resubmit. All approvers are notified again. Previous comments remain visible.

No approvals — direct finalise

When approvals are off, the author can mark the document as Final directly from the document page. Status moves from Draft → Final immediately.

Approver review page

A lightweight read-only page accessible via the email link. Shows the full document with all sections. Two action buttons: Approve and Request Changes (with comment field). No other functionality — approvers cannot edit.

Templates
Default templates for SOW and CR. Users can also save any completed document as a custom template for future reuse.
10
Template types
Default templates

Built-in templates

Two default templates ship with the app: Standard SOW (all 6 sections with placeholder hints) and Standard CR (change-type driven, shorter). Always available, cannot be deleted.

Custom templates

Saved by user

Any completed SOW or CR can be saved as a template. Common use: save an Acme Corp SOW as a template so the next engagement for the same client starts pre-filled.

How to save a template
Step 1

Open any completed doc

SOW or CR in any status (Draft, In Review, Final). The "Save as template" option is in the document actions menu.

Step 2

Name the template

Give it a descriptive name (e.g. "Acme Corp SOW" or "Standard 3-month extension CR"). Choose whether to include real values or replace with placeholder hints.

Step 3

Use it next time

Template appears in the library. When selected, it pre-fills the guided form. All fields remain editable — the template is a starting point, not a lock.
